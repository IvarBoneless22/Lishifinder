# Lishi Finder

Статичний PWA-каталог сумісності автомобілів і відмичок Lishi. Застосунок не має бекенду чи залежностей: його можна відкрити локально або розмістити в корені GitHub Pages.

## Можливості

- три режими: пошук авто, пошук за кодом Lishi та порівняння джерел;
- фільтри за маркою, ринком, роком і типом ключа;
- локальні векторні значки марок у фільтрі, швидкому виборі та результатах;
- перегляд реального фото моделі після натискання на її назву;
- окрема панель «Ключ / замок» зі схематичною формою профілю, типом запуску, чипом, рівнем перевірки та фото ключа, коли воно додане;
- імпорт дозволених CSV/JSON для порівняння з вбудованим каталогом;
- власні примітки до кожного запису зі збереженням на пристрої;
- офлайн-режим після першого завантаження;
- позначення записів, які потребують перевірки або не мають підтвердженого коду;
- автоматична перевірка структури каталогу в GitHub Actions.

Каталог містить 919 записів для 20 марок. Окрім початкових марок, додані Alfa Romeo, Fiat, Ford, Genesis, Honda, Hyundai, Kia, Lincoln, Mazda, Nissan, Peugeot та Porsche. Нові записи мають джерело й дату перевірки у `data.js`; ринок США, Європа, Австралія, Близький Схід, Південна Корея, Бразилія, Канада або «Не вказано» зберігається без припущень, тому перед роботою важливо вибрати правильний варіант.

Дані зі скріншотів користувача мають найвищий пріоритет і показуються першими. Якщо інший довідник містить відмінний код Lishi для того самого варіанта автомобіля, цей код не стає основним записом: він зберігається у полях `alternativeLishi`, `alternativeSource` та відображається як примітка.

Фото завантажуються за запитом із Wikimedia Commons і потребують інтернету. У вікні фото показується авторство, ліцензія та посилання на сторінку оригіналу. Автоматичний пошук може підібрати інший рік або покоління, тому зображення також має довідковий характер.

Фото ключів зберігаються окремо від фото автомобілів і прив’язуються до конкретного запису: моделі, років, ринку та типу запуску. Додаються лише оригінальні фотографії користувача або зображення з дозволеним використанням; джерело можна вказати в `keyPhotoSource`. Якщо фото відсутнє, панель показує схематичний контур і не підміняє його випадковим зображенням.

Форми профілів винесені в `profile-catalog.js`, щоб один перевірений профіль застосовувався до всіх пов’язаних моделей без дублювання. Підтримуються `edge`, `laser`, `tibbe`, `fob` і `unknown`. У довіднику окремо позначено форми, підтверджені скріншотами користувача, офіційним джерелом і довідниковою класифікацією, яку ще потрібно звірити. Тип запуску (`ignition`) не використовується як заміна форми профілю: безключовий доступ і форма аварійного леза є різними характеристиками.

Якщо локального дозволеного фото немає, панель дає посилання на офіційний каталог фото-зразків Ilco. Зображення зі сторонніх програм і платних баз не копіюються автоматично: вони використовуються лише для ручної звірки даних.

## Порівняння та власні примітки

Режим «Порівняти» зіставляє записи LishiFinder з даними, які користувач імпортував із дозволеного CSV або JSON. Файл обробляється в браузері та зберігається у localStorage; на сервер він не надсилається. Шаблон міститься у `sample-external-data.csv`.

Підтримувані поля імпорту: `brand`, `model`, `years`, `yearFrom`, `yearTo`, `market`, `lishi`, `chip`, `keyShape`, `keyPhoto`, `keyPhotoAlt`, `keyPhotoSource`, `source`, `sourceUrl`, `note`. Обов’язковими є `brand`, `model` і `lishi`. Також розпізнаються поширені назви колонок `make`, `vehicle`, `tool`, `reference`, `keyway` та українські відповідники.

Примітки зберігаються локально для кожної комбінації автомобіля, років, ринку та Lishi. Кнопка «Експортувати мої дані» створює резервну JSON-копію імпортованих записів і приміток. Такий файл можна імпортувати назад.

LARA та інші платні бази не копіюються і не обходяться. Їхні записи можна додати лише через офіційно дозволений експорт або API.

## Відповідальне використання

Дані мають довідковий характер і не замінюють візуальну та технічну перевірку профілю ключа. Використовуйте застосунок лише під час законних робіт за наявності дозволу власника автомобіля.

## Дані каталогу

Файл data.js містить об’єкт window.LISHI_DATA з версією каталогу та записами такого формату:

- brand, model, years — відображувані дані автомобіля;
- yearFrom, yearTo — нормалізований діапазон для фільтра за роком;
- markets — масив нормалізованих кодів ринків;
- ignition — key, smart, prox або unknown;
- lishi — код Lishi для перевіреного запису;
- alternativeLishi, alternativeSource — альтернативний код і його джерело, коли він суперечить пріоритетному скріншоту користувача;
- chip — код транспондерного чипа, якщо він чітко зазначений у джерелі;
- keyShape — необов’язкове перевизначення форми ключа: `edge`, `laser`, `tibbe`, `fob` або `unknown`; зазвичай форма автоматично береться з `profile-catalog.js` за кодом Lishi;
- keyPhoto, keyPhotoAlt, keyPhotoSource — дозволене фото ключа, його текстовий опис і джерело; локальні файли розміщуються в `assets/key-photos/`;
- status — verified, needs_review або not_available;
- note — причина, чому запис не можна рекомендувати автоматично;
- source, sourceUrl, checkedAt — джерело, посилання та дата перевірки запису (коли доступні).

Перед зміною даних запустіть npm run validate. Перевірка також виконується автоматично для pull request та змін у main. Валідатор перевіряє, що кожний непорожній код Lishi з усіх 919 записів має запис у довіднику форм, а також виводить кількість підтверджених, довідникових і ще не визначених профілів.

## Публікація

1. У GitHub відкрийте Settings → Pages.
2. Виберіть розгортання з гілки main, папка /(root).
3. Після публікації відкрийте адресу GitHub Pages.

Після оновлення сайту офлайн-користувачі можуть натиснути «Оновити офлайн-версію».
